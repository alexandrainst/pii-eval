\subsection{Method}

All documents (PDFs) and images were converted to images using the Python libraries \texttt{fitz} and \texttt{PIL.Image} at \texttt{dpi=150}.

\subsubsection{Model-specific details}

\begin{itemize}[leftmargin=*, itemsep=2pt]
  \item \textbf{PaddleOCR-VL-1.5} was run via the \texttt{paddleocr.PaddleOCRVL.predict} pipeline, joining each \texttt{block\_content} with newlines.
  \item \textbf{Tesseract} was run via the \texttt{pytesseract} library using \texttt{image\_to\_string}.
  \item \textbf{Generative models} were run with the following prompts:
  \begin{itemize}[leftmargin=*, itemsep=2pt]
    \item \emph{System prompt:} ``You are an expert in extracting text from documents and images. You always arrange the extracted output text in a sensible fashion, reflecting the structure of the text as it was found in the source, but not sacrificing a logical final output structure. You always only output the actual text found in the sources --- never your own replies to the prompt, markdown formatting, or other additions.''
    \item \emph{User prompt:} ``Please extract all text from the following content: \textless images(base64)\textgreater.''
  \end{itemize}
\end{itemize}

\subsection{Method}

All models were asked to classify tokens, or to identify substrings within the texts, and assign each to one of the following categories (Danish descriptions in parentheses):

\begin{itemize}[leftmargin=*, itemsep=1pt]
  \item \texttt{BANK\_ACCOUNT} --- bankkontonummer
  \item \texttt{DRIVERS\_LICENSE} --- kørekortnummer
  \item \texttt{EMAIL\_ADDRESS} --- email-adresse
  \item \texttt{IP\_ADDRESS} --- IP-adresse
  \item \texttt{PASSPORT} --- pasnummer
  \item \texttt{PCI} --- betalingskortoplysninger, kortnummer, udløb, CVV
  \item \texttt{PERSON\_NAME} --- personnavn
  \item \texttt{PHONE\_NUMBER} --- telefonnummer (alle landekoder)
  \item \texttt{PRECISE\_LOCATION} --- lokation: gadenavn, husnummer, postnummer, koordinater, etc.
  \item \texttt{SALARY} --- løn: f.eks.\ løntrin, timeløn eller månedsløn-beløb
  \item \texttt{SSN} --- CPR-nummer
  \item \texttt{USERNAME} --- brugernavn (f.eks.\ på online platforme)
  \item \texttt{VEHICLE\_ID} --- registreringsnummer / nummerplade
\end{itemize}

Predicted tokens and substrings were then mapped onto a unified word-tokenisation produced by the \texttt{spacy} library using the Danish model \emph{da\_core\_news\_sm}:
\begin{lstlisting}[language=Python]
nlp = spacy.load("da_core_news_sm")
doc = nlp(text)
\end{lstlisting}
Subsequently, all fine-grained labels were merged into a single \texttt{PII} class, and precision/recall were computed from the true/false positive and negative counts of the \texttt{PII} versus \texttt{O} labels.

\subsection{Biasing and thresholds}

\begin{itemize}[leftmargin=*, itemsep=4pt]
  \item \textbf{eu-pii-safeguard} (HuggingFace: \texttt{tabularisai/eu-pii-safeguard}) was biased using logit \texttt{O}-biasing with a value of $-11.5$. That is, $11.5$ was subtracted from the logit corresponding to the \texttt{O} label prior to applying \texttt{argmax}. In effect, every other label (all of which correspond to some form of PII) becomes more likely to be predicted, yielding higher recall at the cost of precision.

  \item \textbf{gliner-pii} (HuggingFace: \texttt{nvidia/gliner-PII}) is used via the \texttt{gliner} library\footnote{\url{https://urchade.github.io/GLiNER/}}, which provides a built-in threshold parameter for trading off precision and recall. Lower values yield higher recall and lower precision. The default value is $0.5$; the lowest threshold producing recall above $95\%$ on these datasets was found to be $0.0002$, and was used for the results reported above.

  \item \textbf{Qwen3.5-397B} was run with the following prompts:
\end{itemize}

\begin{lstlisting}

information) in contexts that may be in languages other than English
(multilingual). Answer so that the entire output always deserialises
